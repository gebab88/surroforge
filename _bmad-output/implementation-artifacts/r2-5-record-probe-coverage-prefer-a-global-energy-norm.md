# Story R2.5: Record probe coverage; prefer a global energy-norm

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As an auditor,
I want the field run to record **how much field energy its reproduce verdict actually verifies** (`probe_coverage_energy`), and to **warn — not silently pass — when that coverage is low**,
so that a green "reproduced" can never hide divergence in the part of the field the verdict cannot see (the truncated modes), and the run's lineage states the verified fraction on its face.

## Acceptance Criteria

1. **Given** a persisted **field run** (a run carrying a reduction / `basis_hash`) **when** it is persisted **then** `probe_coverage_energy` — the fraction of the field's total energy that the verified, reconstructed field represents (the retained-mode POD energy share; out-of-probe energy = `1 − probe_coverage_energy` = the truncation floor) — is recorded in `lineage.json` as a top-level field, in `[0.0, 1.0]` (a non-degenerate field is in `(0.0, 1.0]`; a constant / zero-energy field yields `0.0` — reduced_field.py:115-117 — an edge outside the test fixture).
2. **Given** the as-built field verdict **then** the **global field-energy norm over the full reconstructed holdout field IS the definition** (already shipped in R2.3 via `services._field_energy_relative_diff` — every field DOF is in the comparison, there is no spatial node subset in v1). This story makes that explicit in code/docs and records the coverage that the global norm verifies. Energy-weighted **probe-node subsampling** (a strict subset of DOF as a fast path; Q-DEIM/QR, ideas #49/#84) stays **deferred to Phase 2** — in v1 "the probes" are the full field, so the only coverage gap is modal truncation.
3. **Given** a field run whose `probe_coverage_energy` is below a single named threshold **when** `reproduce()` runs **then** it **emits a `FieldCoverageWarning`** (rendered by the CLI as a sober `Warning:` line, like `ProvenanceWarning`) stating that the verdict verifies only that fraction of the field — **a warning, never a gate**: the verdict and `assert_reproducible` are unchanged, the run still reproduces, and exit status is unaffected. A high-coverage field run emits **no** such warning.
4. **Given** a **scalar run** (no reduction) **then** nothing changes: `probe_coverage_energy` is **absent** from scalar lineage, no `FieldCoverageWarning` is ever emitted, and the scalar reproduce path stays **byte-identical** (the R2.4 guard still passes; it gains an assertion that `probe_coverage_energy` is likewise absent).
5. **Given** this behaviour **when** CI runs **then** a dedicated test pins it under the existing `reproducibility (pinned threads)` job; the assertions are **BLAS-robust** (coverage is SVD-derived ⇒ ULP-sensitive on Apple Accelerate, so assert **bounds and warn/no-warn margins**, never bit-equality of the coverage float and never a golden literal).

> **Scope boundary (do not exceed).**
> - **The verdict is FROZEN. R2.5 adds a record + a warning + docs; it must NOT change `_verdict`, `_field_energy_relative_diff`, `assert_reproducible`, the tolerance, or the spec hash.** Coverage is **diagnostic/advisory**, exactly like `basis_hash` — never a gate (`spec-field-rom-fingerprint.md`, decision #4 establishes the "diagnostic, not a gate" pattern for this kind of metadatum).
> - **Do NOT implement probe-node subsampling / Q-DEIM / QR probe selection (#49/#84).** v1 uses the full field as the global energy-norm; node subsampling is Phase-2 (OQ-3). Record coverage as the modal-truncation share, document the deferral, and leave the door open (a distinct lineage field, so a future subset design can lower it below `energy_captured`).
> - **Do NOT change the scalar path by one byte** (R2.4). The new lineage key and the warning are **field-gated** (written only inside the `field_extras` branch / only when `is_field`).
> - **Do NOT introduce the physics/bitwise two-verdict (#73), per-mode bands (#72), or `basis.npz` persistence** — all deferred or superseded.
> - **Do NOT edit the `<frozen-after-approval>` block** of `spec-field-rom-fingerprint.md`. Its "energy-weighted probe **nodes**" language is superseded by the as-built global-energy-norm (this was already the R2.3 reality and OQ-3's explicit recommendation); record that with a one-line "superseded by R2.5 — v1 uses the full field; node subsampling deferred" note **outside** the frozen block (the same pattern as the R2.3 deferral note).

## Dev Notes

### The central realization (read this first — it scopes the story)
**R2.5 is a record + warn + document story. The verdict is already correct and frozen.** R2.3 shipped the field verdict as the **global field-energy-relative diff over the FULL reconstructed out-of-sample holdout field** (`services._field_energy_relative_diff`, services.py:169; the fingerprint is the whole reconstructed field, all DOF, capped at 512 holdout *rows* — see `engine._FINGERPRINT_MAX_ROWS`). There are **no probe nodes** in v1 — "the probes" are the entire field. So:
- **Spatial coverage is already 100 %** (every field DOF is in the verdict). The frozen spec's "energy-weighted probe **node** subsampling" (coverage 0.621 in the spike) was **not** built; OQ-3 explicitly argued to "prefer the global energy-norm as the definition with probes as the fast path," and the as-built R2.3 + this story's title (*prefer a global energy-norm*) confirm that choice. Node subsampling (Q-DEIM/QR #49/#84) is Phase-2.
- **The only coverage gap in v1 is modal truncation.** The reconstructed field omits the truncated tail modes, so the verdict cannot see a divergence living purely there. `probe_coverage_energy = energy_captured` (e.g. 0.999) is therefore the honest "fraction of the field the verdict verifies"; `1 − probe_coverage_energy` is the truncation floor.

So the work is: (a) record that already-computed number as a first-class lineage field; (b) warn when it is low so "reproduced" can't masquerade as a full-field guarantee; (c) document the global-norm-is-the-definition decision and the node-subsampling deferral. **Expect a small, additive diff** across `reduced_field.py`, `engine.py`, `run.py`, `services.py`, `cli/main.py`, plus tests and one CI line. No verdict logic changes.

### What `probe_coverage_energy` means concretely
- **Value:** the retained-mode POD energy share = `self._energy_captured` (already computed in `ReducedFieldTrainer.fit`, already inside `reduction["energy_captured"]`). Recorded ALSO as a distinct top-level lineage field so a future node-subset design can report a *lower* value without overloading the `reduction` record.
- **Semantics:** the fraction of the field's total energy that the global-energy-norm verdict actually verifies. Out-of-probe energy = `1 − probe_coverage_energy` = the truncation floor (the part reproduce cannot check in v1).
- **Relationship to R3.2 (two-source error):** R3.2 (deferred) will *report* the truncation floor vs. surrogate error for model-quality purposes. R2.5 only records the coverage in lineage and warns at reproduce time for *verdict-trust* purposes. Same underlying number (`energy_captured`), different concern — R2.5 does **not** build the report. No scope collision.

### Diagnostic, never a gate (the contract pattern to follow)
Coverage behaves exactly like `basis_hash`: recorded, surfaced, advisory — **never** in `_verdict`, `assert_reproducible`, the tolerance, or the spec hash. `spec-field-rom-fingerprint.md` decision #4 ("basis hash → diagnostic, NEVER a gate") is the precedent; follow it. A low-coverage run still **reproduces** (the re-run reconstructs the same low-energy field); the warning is the "not a silent pass" signal, not a failure. The warns-but-doesn't-gate test (Task 6) pins both halves: warning emitted AND verdict/`assert_reproducible` unchanged. **Legacy field runs:** a field run trained before R2.5 has `basis_hash` (so `is_field=True`) but no `probe_coverage_energy` key; `parent.probe_coverage_energy` then returns the `1.0` accessor default ⇒ no warning. That is the correct degradation — old field runs simply do not warn.
